# 실행 종료와 시간 예산

LLM이 자료를 확보했더라도 최종 응답을 내지 못하면 완료가 아니다. DustAgent는 최종 결과, 모델 턴 기록, 실제 도구 응답을 분리해서 반환한다.

```sh
dust run crawler --json --max-turns 15 --timeout-ms 120000 --tool-timeout-ms 15000 "URL"
dust run crawler --report reports/crawl.json "URL"
```

## 결과 계약

ExecutionReport는 stop_reason, output, turns_used, elapsed_ms, turns, tool_calls, validation, error, warnings를 담는다. 종료 사유는 completed, turn_limit, time_limit, tool_timeout, empty_response, execution_error, validation_failed, cancelled다. completed는 비어 있지 않은 최종 응답을 받았고 설정된 output_schema와 검사기가 있다면 통과했다는 뜻이다. 실제 작업 전체를 끝냈다거나 모든 링크를 관찰했다는 뜻은 아니다.

각 모델 턴은 응답 내용과 요청한 도구 개수, 소요 시간, 오류를 기록한다. 각 도구 호출은 이름, 인자, 성공/실패/시간초과/인자오류, 실제 응답, 소요 시간과 잘림 여부를 기록한다. 도구 응답에 발견 290 / 관찰 100 / 남은 190 같은 메타데이터가 있으면 그대로 남긴다. 코어가 없는 범위 정보를 만들어 내지는 않는다.

턴·시간 소진 후 output에 마지막 중간 응답이 남을 수 있다. 이것을 최종 결과로 사용하지 않도록 기본 raw 출력은 완료 시에만 STDOUT으로 내보낸다. --json은 실패 보고서도 출력한다. 실패 여부는 종료 코드로 함께 판단한다.

종료 코드: 완료 0, CLI 입력·설정·파일 오류 1, 턴 소진 2, 전체/도구 시간 소진 3, 모델 빈 응답 4, 실행 오류 5, 결과 검사 실패 6, 취소 7. ACP 취소는 프로세스를 종료하지 않고 원래 prompt 요청에 stopReason=cancelled를 반환한다. 도구 오류 후 모델이 복구해서 응답할 수는 있지만 오류 기록은 지워지지 않는다. 오류가 있는 실행은 성공 사례로 승격할 수 없다.

## 시간과 종료 관리

기본 전체 예산은 300000ms, 도구 호출당 30000ms, 모델 턴 수는 10이다. 매니페스트 timeout_ms, tool_timeout_ms, max_turns로 설정하고 CLI 옵션으로 덮어쓴다. 시간 값은 1~86400000ms다.

CLI의 전체 예산은 MCP 시작과 경험 검토부터 모델/도구 호출까지 연결된다. 라이브러리 execute_report는 도구 목록 조회와 모델/도구 실행을 포함하며 init_scoped_mcp는 별도로 제한한다. 동기 입력·저장소 읽기·보고서 쓰기에는 강제 중단을 적용하지 않는다.

도구 시간초과는 실행을 즉시 중단한다. 취소한 stdio 요청의 늦은 응답이 다음 요청에 섞이지 않도록 해당 클라이언트를 제거한다. 외부 서버에서 작업이 이미 수행됐는지는 알 수 없으며 자동 재시도하지 않는다. 취소 후 클라이언트 정리에 최대 1초, 전체 shutdown에는 별도 최대 5초를 허용한다. 정리 오류는 보고서 warnings에 남긴다.

## 결과 검사와 기록 제한

`output_schema`가 있으면 최종 응답을 먼저 JSON으로 파싱하고 선언한 제약을 확인한다. 실패 사유는 모델에 돌려주며 기존 턴·시간 예산 안에서 계속한다. 스키마를 통과한 뒤 `validation` 검사기가 실행된다. 검사기의 기본 legacy 모드는 실패 시 validation_failed로 종료하고, feedback 모드는 complete/continue/blocked 판정을 받아 continue이면 같은 예산 안에서 실행을 이어간다. 원본 응답과 검사 이력을 보고서에 남긴다. 경험 저장소에는 검사 근거를 함께 기록하며, 실패/미완료 실행은 성공 사례가 되지 않는다. 스키마 키워드와 크기 제한은 [[15_완료_피드백_및_실행_복구]]를 참고한다.

도구 응답 기록은 호출당 최대 64 KiB, 모델 중간 응답 기록은 턴당 최대 4 KiB, 두 기록의 문자열 합계는 최대 1 MiB다. 잘림 여부를 표시하며 도구 결과가 잘리면 모델에도 더 좁은 결과를 요청하라는 피드백을 보낸다. 최종/부분 output와 도구 인자는 별도로 남기며 이 문자열 제한에 포함하지 않는다. 따라서 전체 JSON 파일 크기를 1 MiB로 보장하지 않는다.

--report는 종료 시 JSON 파일을 임시 파일에 쓴 뒤 원자적으로 교체한다. Unix 파일 권한은 0600이다. 보고서에는 입력 인자와 실제 도구 출력 같은 민감한 내용도 포함될 수 있다.

종료 보고서는 실행 중 저장하는 체크포인트와 별개다. 프로세스 재시작 후 이어가는 방법과 재개를 차단하는 조건은 [[13_체크포인트_및_재개]]를 참고한다. 브라우저 세션은 복원하지 않는다.

실행 루프의 일시적인 모델 요청 실패는 제한된 재시도로 복구한다. 검사 피드백·재시도 기록·작업 메모의 세부 계약은 [[15_완료_피드백_및_실행_복구]]를 참고한다.

원문 대화와 도구 결과는 보고서 잘림 전에 별도 아카이브에 보존한다. 자동 compact 호출도 턴·시간 예산을 소비하며, 요약 이력은 compactions에 분리해 기록한다. 전체 기록·조회 방법은 [[18_컨텍스트_압축_및_원문_기록]]을 참고한다.

## 턴 소진 후 마무리 옵션

기본값은 꺼짐이다. 매니페스트에 `"wrap_up_on_limit": true`를 지정하거나 CLI에 `--wrap-up-on-limit`를 주면 `max_turns` 소진 후 마무리용 3턴을 한 번 추가한다. `--wrap-up-on-limit=false`로 매니페스트 설정을 끌 수 있다. `dust run`과 `dust acp` 모두 지원한다.

```sh
dust run crawler --max-turns 10 --wrap-up-on-limit "조사 결과를 JSON으로 반환해"
dust run crawler --wrap-up-on-limit=false "일반 턴 예산만 사용해"
```

마무리 시작 시 사용자 역할의 런타임 안내를 원문 대화와 체크포인트에 기록한다. 모델에 남은 3턴 안에 기존 출력 형식을 지켜 마무리하고, 미완료 작업과 불확실성을 명시하도록 요청한다. 도구와 출력 검증은 계속 사용할 수 있고, 정상 완료하면 즉시 종료한다. 추가 3턴도 소진하면 `turn_limit`으로 끝나므로 최종 응답 생성을 보장하지 않는다.

`turns_used`에는 추가 턴도 포함하고 `warnings`에 마무리 시작을 기록한다. 기존 실행 루프 기준이므로 압축 호출과 출력 수정도 턴을 소비한다. 전체 시간 제한·취소·오류·결과가 불확실한 도구 호출의 중단 규칙은 그대로 적용하며 시간을 연장하거나 도구를 자동 재실행하지 않는다. `resume`과 ACP 후속 prompt는 호출마다 새 예산을 부여하므로 옵션이 켜져 있으면 각각 마무리 예산도 새로 적용한다.

## 남은 예산 안내

기본값은 꺼짐이다. 매니페스트에 `"budget_notice": true`를 지정하면 모든 모델 요청 끝에 운영자 안내 한 줄을 붙인다. 예: `Model turn 4 of 10; 6 more after this one, about 52 of 60 minutes left`. 남은 턴이 전체의 3분의 1 이하가 되면 새 탐색을 멈추고 가장 강한 결과를 확인하라고 안내하고, 마지막 턴이거나 남은 시간이 10% 이하면 도구 없이 지금 최종 응답을 쓰라고 요청한다. `wrap_up_on_limit`이 켜져 있으면 마지막 정규 턴에서 마무리 턴이 이어짐을 알리고, 마무리 턴은 `Wrap-up turn 1 of 3`처럼 표시한다.

안내는 해당 요청에만 덧붙이며 원문 대화·체크포인트·기록에 저장하지 않는다. 요청 끝에 붙이므로 앞부분의 프롬프트 캐시는 그대로 유지된다. 어떤 한도도 바꾸지 않는다.

# 체크포인트와 재개

호출한 에이전트가 실행 예산을 나눠 쓰거나 DustAgent 프로세스가 종료된 뒤 이어가도록 대화와 확인된 도구 결과를 저장한다. 코어에 스케줄러나 자동 무한 재시도를 추가하지 않고, 호출자가 다음 실행을 결정한다.

CLI `dust run`은 `--checkpoint`나 `--resume`이 없으면 시스템 임시 디렉터리에 실행마다 고유한 `dust-run-XXXXXX/state.json` 경로를 만든다. 보통 `/tmp` 아래이며 `TMPDIR` 설정을 따른다. 경로는 stderr의 `[dustagent] checkpoint: ...`와 JSON 보고서의 `checkpoint_path`에 표시한다. 일반 stdout은 기존 작업 결과만 유지한다.

```sh
dust run crawler --max-turns 10 --json "URL"
# 보고서의 checkpoint_path를 사용한다. 아래 경로는 예시다.
dust run crawler --resume /tmp/dust-run-XXXXXX/state.json --max-turns 10 --json
```

자동 경로의 디렉터리는 Unix에서 0700, 체크포인트 파일은 0600이며 프로세스가 종료돼도 삭제하지 않는다. 명시한 `--checkpoint`·`--resume`은 자동 경로보다 우선한다. 초기화 실패 등으로 실행이 시작되지 못하면 경로만 정해지고 state.json이 아직 없을 수 있다. 임시 파일 정리 정책이나 직접 삭제로 파일이 없어질 수 있으므로 오래 보존할 작업은 명시 경로를 사용한다. 자동 생성은 CLI run에 적용되며 라이브러리와 ACP 세션은 기존처럼 명시적으로 저장을 연결해야 한다.

```sh
dust run crawler --checkpoint state/crawl.json --max-turns 10 "URL"
dust run crawler --resume state/crawl.json --max-turns 10 --json
```

첫 실행은 새 파일을 요구한다. 재개는 저장된 원래 입력과 대화를 유지하며, 선택적인 입력 문장을 새 사용자 메시지로 추가할 수 있다. 추가 입력 없이 재개하면 기존 작업만 이어가고 STDIN은 읽지 않는다. 같은 매니페스트 내용과 작업 디렉터리가 필요하다. 전체 대화와 이전 실행 기록을 복원하며, 턴 번호와 경과 시간은 누적된다. 각 호출의 턴·시간 예산은 추가 예산이다. 재개할 때 새로운 few-shot 사례를 끼워 넣거나 실행 전 자동 사례 검토를 반복하지 않는다.

## 추가 프롬프트로 결과 교정

```sh
dust run crawler --resume /tmp/dust-run-XXXXXX/state.json --max-turns 5 "이전 결과를 지정된 JSON 스키마에 맞게 수정하세요."
```

저장된 대화 끝에 추가 프롬프트를 하나의 사용자 메시지로 붙인다. 원래 입력과 이전 도구 기록은 덮어쓰지 않으며, 수행한 도구를 런타임이 자동 재실행하지 않는다. 모델이 추가 도구 호출을 선택할 수는 있다. 후속 요청도 이번 호출의 턴·시간 예산을 따른다.

추가 프롬프트는 대화와 원문 기록에 저장되므로 다음 재개에서도 남는다. compaction의 현재 요청에는 최신 저장 사용자 메시지를 사용한다. 검사기와 경험 기록의 `input`은 기존 계약대로 원래 작업 입력이며, 새 프롬프트로 바꾸지 않는다. 검사기 자체에 새로운 스키마를 적용하려면 매니페스트를 바꾸는 방식으로 같은 체크포인트를 재개할 수는 없으므로 별도 앱 실행을 사용한다.

라이브러리 API는 `resume_report_with_prompt(seed, Some(prompt))`와 `resume_report_with_prompt_and_experience(seed, Some(prompt), store)`다. 기존 `resume_report` 계열은 추가 프롬프트 없는 동작을 유지한다. 공백뿐인 추가 프롬프트는 허용하지 않는다.

추가 프롬프트가 있는 재개는 기존 원문 아카이브의 복사본에 기록합니다. 새 체크포인트 저장에 실패해도 이전 체크포인트와 원문은 그대로 유효하므로 다시 재개할 수 있습니다.

## 보고서로 경로 찾기

`--report run-report.json`으로 종료 보고서를 저장하면 일반 stdout 출력을 유지하면서 `checkpoint_path`를 확인할 수 있다. JSON 보고서는 체크포인트 파일 자체가 아니므로 보고서 경로를 `--resume`에 넣으면 안 된다.

```sh
dust run crawler --max-turns 1 --report run-report.json "URL"
```

재개하려면 보고서에 적힌 실제 체크포인트 경로를 사용한다. 종료 코드를 먼저 확인하고, 해당 파일이 존재하며 재개 가능한 상태인지 확인해야 한다. 완료된 실행은 비어 있지 않은 추가 프롬프트가 있어야 이어갈 수 있다. 결과가 불확실한 도구 호출은 추가 프롬프트가 있어도 재개를 거부한다.

## 패키지와 skill 내용 검사

패키지 실행은 추출 경로 대신 내용 해시를 확인한다. 같은 .dustpkg가 매번 다른 임시 디렉터리에 풀려도 재개할 수 있으며, 패키지 또는 선언한 skill 내용이 바뀌면 모델 호출 전에 거부한다. 작업 디렉터리는 여전히 같아야 한다.

```sh
dust run ./coverage-reader-0.1.0.dustpkg --checkpoint state/coverage.json --max-turns 1 "입력"
dust run ./coverage-reader-0.1.0.dustpkg --resume state/coverage.json --max-turns 5 --json
```

단일 JSON 앱에 skills가 선언되어 있으면 매니페스트 옆 skills/의 내용에 연결한다. 전체 패키지 내용 바인딩과 라이브러리의 LoadedApp 수명은 [[14_앱_패키지_및_스킬]]을 참고한다.

## 어디서 이어갈 수 있나

모델 요청 직전과 도구 호출 묶음의 모든 결과를 확인한 직후에 Ready 상태를 저장한다. 턴 소진, 모델 요청 오류, 모델 응답 대기 중 프로세스 종료는 마지막 Ready 상태에서 이어갈 수 있다. 저장된 도구 호출을 런타임이 자동으로 다시 실행하지 않는다. 모델이 비슷한 작업을 새로 요청하는 것까지 방지하지는 않는다.

도구를 보내기 전에 ToolInFlight 상태를 디스크에 저장한다. 실행 중 종료되거나 시간초과·전송 오류 때문에 결과를 확인하지 못하면 자동 재개를 차단한다. 여러 도구 중 일부만 끝났더라도 묶음 전체가 확인되지 않았다면 같은 원칙을 적용한다. 외부 작업은 수행됐지만 결과 저장 전에 프로세스가 죽었을 수 있으므로 정확히 한 번 실행을 보장하지 않는다. 호출자는 외부 상태를 확인하고 별도 작업을 설계해야 한다. 강제 재개 옵션은 없다.

최종 결과 검사 전에는 ValidationInFlight를 저장한다. 중단된 검사, legacy 검사 실패, feedback의 blocked 판정은 재개를 허용하지 않는다. feedback의 continue 판정은 피드백을 저장한 Ready 상태에서 이어갈 수 있다. 완료된 Finished 체크포인트는 비어 있지 않은 추가 프롬프트가 있을 때만 새 대화를 이어간다. 추가 프롬프트가 없는 Finished 재개는 계속 거부한다. 종료 보고서의 stop_reason과 체크포인트의 phase는 서로 다른 정보다.

## 저장과 프로세스 경계

체크포인트에는 원래 입력, 시스템 프롬프트, 대화, 도구 결과와 실행 보고서가 포함된다. 임시 파일 쓰기·파일 동기화·원자적 교체를 사용하며 Unix에서는 디렉터리도 동기화한다. 파일 권한은 0600이고 읽기와 쓰기 모두 32 MiB로 제한한다. 체크포인트 저장에 실패하면 다음 도구를 실행하지 않고 오류로 종료한다.

CLI는 같은 체크포인트를 동시에 쓰지 못하도록 옆의 .lock 파일에 OS 잠금을 유지한다. 잠금 파일은 남아도 프로세스 종료 시 잠금은 풀린다. --report는 체크포인트와 같은 경로를 사용할 수 없다. 부트스트랩 단계가 끝나 실행 루프에 진입하기 전에 종료되면 새 체크포인트가 없을 수 있다.

MCP 서버는 새 프로세스로 시작한다. 브라우저 탭·로그인·메모리·원격 트랜잭션 상태는 복원하지 않는다. 과거 도구 결과는 당시 관찰이며 현재 원격 상태라는 보장은 없다. 세션 의존 작업은 도구 자체의 영속 상태와 재연결 계약이 필요하다.

라이브러리에서는 DustCore::with_checkpoint(path)와 resume_report 또는 resume_report_with_experience를 사용한다. 재개에도 저장 경로가 필요하다. CLI와 달리 라이브러리 호출자는 동일 파일의 배타적 접근을 직접 보장해야 한다.

## 검증 범위

단위·통합 테스트는 매니페스트/디렉터리 바인딩, 대화 순서, 저장 실패 전 도구 차단, 불확실한 도구 결과의 재개 차단을 확인한다. 실제 CLI 프로세스를 강제 종료한 뒤 새 프로세스로 재개하는 테스트는 로컬 모의 HTTP 모델과 내장 도구를 사용한다. 이 검증은 외부 브라우저 세션 복원이나 실서비스 크롤링의 완주를 증명하지 않는다.

# 사례 기반 자동 강화

DustAgent는 실행 사례를 모으고, 강화 Agent가 요청과 결과를 조사해서 다음 실행에 참고할 사례를 선별한다. 모델 가중치를 수정하지 않고 few-shot으로 활용한다. 호출 Agent가 UUID를 추적하거나 개별 사례를 승인할 필요가 없다.

## 사용법

```sh
# 옵션은 입력보다 앞에 둔다.
dust run commit_gen --experience "diff 내용 ..."
# 미검토 사례 조사 및 선별 결과 저장
dust learn commit_gen
# 기록과 선별 이유 조회 — 모델 호출 없음
dust learn commit_gen --list
# 이전 기록 자동 검토 → 관련 사례 활용 → 새 실행 기록
dust run commit_gen --experience "새 diff 내용 ..."
```

`dust learn`의 STDOUT은 reviewed, selected, rejected, skipped 개수가 담긴 JSON이다. `--list`는 입력, 출력, 완료 여부, 선별 여부, 검토 이유를 JSON으로 출력한다. 실행 식별자는 저장소 내부 처리용이며 CLI에 노출하지 않는다. 기존 승인 이벤트와 UUID가 있는 기록도 읽을 수 있다.

## 강화 Agent가 조사하는 것

1. 현재 매니페스트의 역할, 출력 형식과 기록된 요청/응답을 읽는다.
2. raw_json은 JSON 파싱, search_replace_patch는 패치 블록 존재 여부를 검사한다. 기존 diff 표기도 SEARCH/REPLACE 형식의 별칭으로 검사한다.
3. validation 설정이 있으면 실제 검사 프로세스를 실행한다. 실패하면 즉시 사례에서 제외한다.
4. 지정한 문서 URL을 가져오거나, 모델이 작업에 맞는 공식 문서 URL 최대 2개를 제안하고 실제 내용을 가져온다.
5. 검사 결과와 문서 발췌를 함께 읽고 모델이 요청 충족 여부, 관련성, 오류, 근거 없는 주장과 불확실성을 평가한다.
6. 엄격한 JSON 판정과 이유를 검증한 뒤 선별/제외 결과를 저장한다.

이미 검토한 기록은 반복 평가하지 않는다. 한 번에 최신 미검토 완료 기록 최대 10개를 검토한다. 잘못된 판정 JSON이나 도구 호출은 선별로 인정하지 않는다. 자동 검토 실패 시 run은 STDERR에 이유를 기록하고 기존 선별 사례로 작업을 계속한다. learn은 실패 상태로 종료한다. 앞선 정상 검토는 저장되므로 재시도 시 이어서 처리한다.

## 실제 검사 설정

```json
{
  "validation": {
    "command": "python3",
    "args": ["examples/validators/check_summary.py"],
    "timeout_ms": 5000
  },
  "research": {
    "urls": ["https://www.rfc-editor.org/rfc/rfc8259.txt"]
  }
}
```

매니페스트에 선언된 고정 command와 args만 실행한다. 모델이 검사 명령을 생성하거나 바꿀 수 없다. 셸 문자열 치환은 하지 않고 기록의 {input, output}를 STDIN JSON으로 전달한다. checker는 실제 검사를 한 뒤 {passed: boolean, reason: string}만 STDOUT에 출력한다. 종료 코드 0과 passed=true를 모두 만족해야 한다. 일반 cargo test를 그대로 지정하면 로그가 판정 JSON이 아니므로 실패한다. 검사 결과를 JSON으로 정리하는 wrapper가 필요하다.

시간 제한은 기본 5초, 설정 범위는 1~60초다. stdout/stderr 각각 8 KiB를 넘기면 실패하며, 타임아웃 시 직접 실행한 프로세스를 종료하고 회수한다. 자식 프로세스 트리 전체 격리 환경은 제공하지 않는다. 명령은 현재 작업 디렉터리와 환경에서 실행하므로 앱 작성자가 의도한 검사만 선언한다. 로그 stderr는 모델 근거로 전달하지 않는다.

apps/checked_summary.json과 examples/validators/check_summary.py는 저장소 루트에서 실행하는 예시다. JSON 키와 문자열 길이만 검사하므로 요약의 사실 정확성을 증명하지 않는다. 필요하면 앱 목적에 맞는 테스트·스키마·결과 비교를 checker에 구현한다.

## 외부 자료 조사

CLI의 dust learn 및 --experience 실행은 외부 문서 조사를 자동으로 사용한다. research.urls가 없거나 비어 있으면 모델이 공식 문서 URL 후보를 제안한다. 이는 검색 엔진 검색이 아니라 URL 후보 선택과 실제 GET 조회다. 후보 URL 자체는 근거가 아니며 실제 HTTP 응답만 근거로 기록한다.

문서당 10초 제한, 두 URL 병렬 조회, 본문 최대 32 KiB 수신, 발췌 최대 8 KiB다. URL, HTTP 상태, 조회 시각, 발췌, 잘림 여부, 실패 이유를 저장한다. 실패한 조회는 빈 발췌와 오류로 모델에 전달하며 성공한 자료로 취급하지 않는다. 공개 HTTP(S) 주소만 허용하고 DNS로 확인한 공개 주소에 연결한다. 리다이렉트·프록시·인증 URL은 사용하지 않으며 HTML, 텍스트, JSON 자료만 지원한다. PDF나 로그인 페이지, 검색 엔진 전용 API는 지원하지 않는다.

외부 문서는 모델에 참고 자료로 전달되며 명령으로 취급하지 않는다. 조회한 발췌에 없는 내용이나 전체 문서 검토를 했다고 주장하지 않도록 검토 프롬프트에 명시한다. 검사 통과는 검사 항목에 대해서만, 문서 근거는 실제 발췌에 대해서만 의미가 있다. 실제 품질 향상은 전후 평가로 측정해야 한다.

새 의존성, 상주 프로세스 없이 기존 Rust HTTP/Tokio 기능으로 구현했다. apps/reinforcer.json은 같은 판정 프롬프트를 독립 실행하는 앱이며 자동 검사·조회 연결은 CLI/라이브러리에 있다. 앱 파일 수정은 CLI 내장 규칙을 바꾸지 않는다. 입력, 출력, checker 이유와 외부 발췌는 검토용 모델 API에 전달되며 추가 모델 호출이 발생한다.

## 저장과 크기 제한

- 기본 경로: ~/.dustagent/experiences/. run과 learn 모두 --experience-dir PATH 지원.
- 매니페스트 전체 SHA-256으로 사례 집합을 분리한다. 검사 명령이나 조사 설정을 추가·변경하면 기존 선별을 이어받지 않고 새 사례 집합을 시작한다. 이전 파일은 남으며 이전 매니페스트로 조회할 수 있다. CLI 모델 override는 집합을 바꾸지 않는다.
- 검색: Unicode 영숫자 단어 일치. 최대 3개 사례, 입출력 합계 8 KiB 주입.
- 검토할 사례도 입출력 합계 8 KiB까지만 모델에 전달한다.
- JSONL 파일 하나 최대 8 MiB, 입력/출력 각각 최대 16 KiB. 잘린 사례는 선별 대상에서 제외한다.
- Unix 저장 디렉터리 0700, 파일 0600. 입력/출력은 로컬에 저장되며 모델 검토 시 API로 전달된다.
- 같은 저장소의 동시 쓰기는 지원하지 않는다. 호출 Agent가 쓰기를 직렬화한다.

라이브러리는 ExperienceStore, reinforcement::reinforce(), DustCore::execute_with_experience()로 각 단계를 조합한다. reinforce()는 명시된 research 설정을 사용하고 reinforce_with_research()는 설정이 없어도 문서 후보를 조사한다. 자동 검토 연결은 CLI에 있으며 기존 execute()는 기록하지 않는다.

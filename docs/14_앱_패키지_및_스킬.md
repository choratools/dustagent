# 앱 패키지와 자기 skill

앱의 배포 단위는 app.json과 자기 skills를 담은 디렉터리다. 전역 skill 목록을 노출하지 않는다. 기존 단일 JSON 앱도 계속 실행할 수 있다.

```text
coverage-reader/
├── app.json
├── skills/
│   └── coverage/
│       ├── SKILL.md
│       ├── references/
│       ├── scripts/
│       └── assets/
├── README.md
└── LICENSE
```

```json
{
  "name": "coverage-reader",
  "package": {"name": "coverage-reader", "version": "0.1.0", "dust_version": ">=0.1.0"},
  "skills": ["coverage"],
  "system_prompt": "Use the coverage skill to assess supplied evidence.",
  "mcp_servers": {}
}
```

## 읽기 계약

[Agent Skills 규격](https://agentskills.io/specification)의 SKILL.md YAML frontmatter와 references/scripts/assets 구조를 사용한다. name은 폴더와 일치하는 1~64자 소문자·숫자·하이픈이며 앞뒤 하이픈과 연속 하이픈을 허용하지 않는다. description은 비어 있지 않은 최대 1024자다. compatibility와 metadata를 지원하며 allowed-tools는 실행 권한으로 해석하지 않는다.

시작할 때 선언된 skill의 이름·설명만 모델에게 제공한다. 모델은 dustagent__read_skill에 skill과 선택적 path를 전달한다. path를 생략하면 SKILL.md를 읽는다. references/rules.md 같은 경로는 해당 skill 기준이다. 다른 앱이나 미선언 skill, 절대 경로, 상위 경로, 심볼릭 링크는 거부한다. 파일은 UTF-8 텍스트이며 최대 64 KiB다. JSON 인코딩을 포함한 도구 응답도 64 KiB를 넘으면 본문을 잘라 전달하지 않고 오류를 반환한다. assets의 바이너리를 패키징할 수는 있지만 텍스트 도구로 읽지 못한다. scripts는 읽기만 제공한다.

예를 들어 도구 인자는 다음과 같다.

```json
{"skill":"coverage","path":"references/rules.md"}
```

manifest의 skills는 도구의 접근 허용 목록이다. 단순히 지침에서 다른 skill을 언급해도 접근할 수 없다. MCP의 dustagent 네임스페이스는 내장 도구용으로 예약되어 있다. 명시적으로 붙인 filesystem MCP나 외부 프로세스까지 격리하는 OS 샌드박스는 아니다.

## 생성·배포·실행

```sh
dust new reader "Summarize supplied documents"
# apps/reader/app.json과 빈 skills/ 생성

dust run ./apps/coverage-reader "discovered=290 observed=100"
dust pack ./apps/coverage-reader --output ./coverage-reader-0.1.0.dustpkg
dust run ./coverage-reader-0.1.0.dustpkg "discovered=290 observed=100"
dust install ./coverage-reader-0.1.0.dustpkg
dust run coverage-reader "discovered=290 observed=100"
```

pack은 원본 디렉터리 밖에 새 .dustpkg를 만든다. 출력 부모 디렉터리는 미리 있어야 한다. 압축 파일은 루트에 app.json이 있는 USTAR tar.gz이며 경로는 USTAR 제한을 따른다. 파일 권한·수정 시각은 내용 식별에 포함하지 않는다. links·특수 파일·중복 항목·경로 탈출·GNU/PAX 확장 항목을 거부한다. 압축 입력은 최대 72 MiB이며, 최대 4096개 항목, 파일당 16 MiB, 전체 64 MiB, 깊이 64를 허용한다. 선언한 skill 전체는 별도로 최대 16 MiB/4096파일/깊이32를 적용한다.

설치는 검증한 파일을 ~/.dustagent/packages/<name>에 저장하며 기존 설치를 덮어쓰지 않는다. DUST_PACKAGE_HOME으로 저장소를 지정할 수 있다. install --store 사용 시 run에도 같은 DUST_PACKAGE_HOME을 지정한다. 원격 레지스트리·업그레이드·서명 검증은 제공하지 않는다. dust_version은 정확한 X.Y.Z 또는 >=X.Y.Z만 지원한다.

설치나 압축 해제 과정은 코드를 실행하지 않는다. run은 매니페스트에 명시된 MCP 서버와 검사기를 기존 실행 계약으로 호출한다. 외부 의존성은 자동 설치하지 않고 상대 명령 경로는 호출자의 작업 디렉터리를 기준으로 한다. 검사기 command/args에 명시한 ${DUST_APP_ROOT}는 현재 패키지 루트로 치환해 패키지 내부 검사기를 호출할 수 있다.

이름 조회는 직접 경로, 기존 JSON 앱 후보, apps/<name> 패키지, 설치 저장소 순서다. 명확한 선택이 필요하면 직접 경로를 사용한다. 압축 파일 실행은 임시 디렉터리 수명을 실행 전체에 유지한 뒤 정리한다.

## 체크포인트와 라이브러리

패키지 내용과 선언한 skill 내용의 해시를 저장한다. 같은 압축 파일이 다른 임시 경로에 풀려도 재개할 수 있다. 매니페스트·작업 디렉터리 검사에 더해 내용이 바뀌면 모델 호출 전 거부한다. 실행 중 외부 프로세스가 로컬 파일을 바꾸는 동작은 지원하지 않는다. 로컬 디렉터리는 실행 동안 그대로 유지해야 한다.

라이브러리에서는 package::load가 반환한 LoadedApp을 실행이 끝날 때까지 유지한다. DustCore::new(...).with_app_resources(&loaded.root, loaded.digest.as_deref())로 skill을 연결한다. 선언한 skill이 있는데 연결하지 않으면 실행을 차단한다. 기존 load_manifest는 매니페스트 옆 skills를 연결한다. load_manifest는 단일 매니페스트용이며 전체 패키지 내용 바인딩에는 package::load를 사용한다.

## 검증 범위

경로 거부·선언 범위·frontmatter·해시 변경·악성 아카이브 입력을 단위 테스트로 확인한다. 실제 CLI pack/install 및 디렉터리·압축·설치 이름 실행은 로컬 HTTP 모의 모델로 검증한다. 외부 모델이 skill을 적절히 선택하는 품질이나 실제 브라우저 실행을 이 테스트가 입증하지는 않는다.

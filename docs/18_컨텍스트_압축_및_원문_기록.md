# 컨텍스트 압축과 원문 기록

모델이 보는 대화와 실행 원문을 분리한다. 원문은 순서대로 추가하는 JSONL에 남기고, 컨텍스트가 커지면 모델에 보낼 오래된 대화만 요약으로 교체한다. 요약이 원문을 덮어쓰지 않는다.

## 보존 범위

앱 지시, 사용자 입력, 모델 응답과 도구 호출, 도구 결과, 모델에 반환하는 검사 피드백을 기록한다. 검사기 subprocess stdout/stderr 전문은 별도 수집 대상이며 이 기능의 원문 대화와 동일하지 않다. 모델 응답은 보고서의 4KiB 제한 전에, 도구 결과는 64KiB/누적 1MiB 제한 전에 저장한다. compact가 켜져 있으면 모델용 도구 결과는 별도로 해결된 trigger_tokens*3/4바이트까지 전달하고 잘린 경우 원문 index를 붙인다. 보고서 도구 기록의 기존 제한은 유지한다. 원문은 Dust가 실제 받은 내용이며, 외부 도구가 반환하기 전에 이미 자른 내용은 복원하지 않는다. 모델의 비공개 reasoning도 원문 대화와 같다고 보장하지 않는다.

기본 저장소는 HOME/.dustagent/history이며 DUST_HISTORY_HOME으로 바꿀 수 있다. 매 실행·ACP 세션마다 별도 디렉터리와 transcript.jsonl을 만든다. Unix 디렉터리는0700, 파일은0600이다. 내용에는 실행 중 받은 데이터가 그대로 들어간다. 자동 삭제·원문 덮어쓰기는 하지 않는다. 레코드당 최대16MiB, 아카이브당 최대256MiB이며 초과·쓰기 실패 시 잘라서 성공하는 대신 중단한다.

## compact 정책

```json
{"compaction":{"enabled":true}}
```

기본값은 모델별 입력 예산에서 계산한다. 앱의 `context_window_tokens` 지정값이 가장 우선하며, 없으면 provider의 한도 정보를 사용한다. Codex는 `$CODEX_HOME/models_cache.json` 또는 `~/.codex/models_cache.json`에서 선택 모델의 `context_window`와 `effective_context_window_percent`를 읽는다. 캐시가 없거나 잘못됐거나 선택 모델이 없으면 한도를 모르는 것으로 처리한다. 자격증명 값은 읽거나 기록하지 않는다. 공식 OpenAI API endpoint는 소규모 정확한 모델 ID 표를 사용한다(gpt-4o-mini/gpt-4o 128000, gpt-6.1-sol 1050000). 다른 endpoint에는 이 표를 적용하지 않는다.

한도를 모르면32768토큰을 보수적인 fallback으로 사용한다. 이는 실제 서버 한도의 보장이 아니다. 로컬 모델·게이트웨이는 실제 배포 한도를 앱에 지정한다.

```json
{"compaction":{"context_window_tokens":32768}}
```

출력용·다음 도구 결과용 여유를 각각 context window의10%(최소1024토큰) 확보하고 나머지를 입력 임계값으로 삼는다. 예를 들어128000이면102400,32768이면26216이다. 이 비율은 Dust의 조정 가능한 구현 정책이며 업계 표준 수치가 아니다. 요약 크기는 임계값의1/8을 추정 토큰 예산으로 삼아 바이트 상한으로 환산한다(256~65536바이트). 최근 내용은 시스템 지시·필수 요청·요약 여유를 포함해 임계값의75% 안에 들어가는 최근 완료 대화부터 보존한다. 필수 요청 또는 최근 도구 묶음 자체가 너무 크면75% 목표를 초과할 수 있지만, 요약 후에도 입력 임계값을 넘으면 새 컨텍스트를 설치하지 않고 중단한다. 성공한 압축 후에는 정상 모델 요청을 진행한다.

`trigger_tokens`, `keep_recent_messages`, `max_summary_bytes`의 기본값0은 자동 계산을 뜻한다. 기존 명시적 숫자 설정은 유지한다. `enabled:false`는 자동 요약만 끄며 원문 기록은 유지한다. 허용 범위는 context_window_tokens4096~10000000, trigger_tokens0 또는1024~1000000, 최근 메시지0 또는2~128, 요약 크기0 또는256~65536바이트다. 카운트는 모델 tokenizer가 아닌 직렬화된 UTF-8 바이트/3에 메시지당16을 더한 추정치다. 별도 토큰 계산 API·매 턴 추가 모델 호출은 사용하지 않으며 정확한 context window 적합성을 보장하지 않는다.

요약은 현재 요청과 유지할 지시를 참고해 **목표·사용자 제약·완료한 작업·결정과 이유·남은 작업·실패와 원인·정확한 식별자/경로/근거 위치·불확실성**을 남긴다. 중복 관찰과 반복 도구 출력은 줄이고, 후속 작업에 필요한 정보의 보존을 우선한다. 요약 요청은 요약 출력 예상량과 여유까지 포함해 설정된 context window 안에 들어가야 한다. 첫 요청처럼 요약할 과거가 없어도 출력 여유를 뺀 최대 입력 예산을 넘으면 모델에 보내지 않고 원문을 유지하며 중단한다.

설계 근거: [Anthropic context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents), [OpenAI compaction](https://developers.openai.com/api/docs/guides/compaction). Dust의 범용 텍스트 요약은 provider의 비공개 reasoning까지 보존하는 전용 compact API와 동일하지 않다.

다음 모델 요청 직전의 안전한 경계에서 오래된 완료 대화를 요약한다. 도구 호출·결과를 중간에서 분리하지 않는다. 앱 시스템 지시와 원래/현재 사용자 요청, 최근 완결된 도구 배치를 보존한다. 요약 요청은 도구 없이 같은 provider로 실행하며 턴·시간 예산에 포함한다. 빈 요약·도구 호출·너무 큰 요약·크기가 줄지 않는 요약은 교체하지 않는다. 실패해도 원문은 남는다.

요약은 assistant 역할의 과거 참고자료로 넣으며 앱 시스템 지시로 승격하지 않는다. 완료 증거를 대신하지 않는다. 생성된 요약 응답도 별도 표시해 아카이브에 보존한다. 원문 기록 범위를 연결해 세부 내용은 내장 도구로 다시 확인할 수 있다. 보고서의 compaction 이력에서 전후 크기와 메시지 수, 원문 범위, 실제 적용한 context window·임계값·요약 상한을 확인한다.

## 원문 안내 색인

압축된 요약만으로는 원문에 무엇이 있는지 알기 어렵다. compact마다 원문 범위와 주제 설명, 실제 등장한 검색어·레코드 번호, 짧은 발췌를 담은 안내 목록을 만든다. 주제 설명은 이미 생성한 요약을 재사용하며 검증된 사실로 취급하지 않는다. 검색어·위치는 Rust에서 원문 문자열로 추출한다. 원문 구간에서 최대10개 위치를 고르게 선택해 발췌하고, 검색어는 최대12개를 남긴다. 도구 이름·인자에 들어 있는 URL/파일 경로도 대상이다. 원문 전체를 대표하는 완전한 의미 색인을 보장하지 않으며, 검색어 목록에 없다는 이유로 해당 내용이 원문에 없다고 판단하면 안 된다. 별도 LLM 호출은 추가하지 않는다.

목록은 `transcript.jsonl` 내부의 별도 metadata 레코드에 누적한다. 메시지 본문이 목록처럼 생겼다고 metadata로 인정하지 않는다. 목록은 원문과 동일한 권한·용량 제한·해시 체인·체크포인트 검증으로 보호한다. 재개할 때 검색어와 발췌가 지정된 원문 레코드에 실제 존재하는지도 확인한다. 각 목록의 범위는 이전 목록 이후 새로 기록된 아카이브 구간이며, 압축 과정에서 실제 제거된 메시지와 정확히 같은 집합이라고 주장하지 않는다. 직전 모델 요약 응답과 이전 색인 metadata를 새 원문의 검색어 근거로 사용하지 않는다.

컨텍스트에는 최신 목록의 짧은 안내와 전체 목록 조회 도구를 남긴다. 안내는 입력 예산에 따라256~2048바이트 이내로 제한하고 UTF-8 경계를 지킨다. 목록 전체를 매번 컨텍스트에 쌓지 않는다. 오래된 목록은 페이지 단위로 조회해 주제·검색어·원문 번호를 확인하고, `history_read`로 실제 내용을 읽는다. 색인 후보와 안내를 먼저 준비해 입력 예산을 다시 검사하고, 통과한 경우에만 metadata를 저장하고 압축된 컨텍스트를 설치한다. 예산 검사에서 거부된 후보는 다음 구간의 시작 위치를 바꾸지 않는다. 목록은 원문 발견을 돕는 것으로 완료 증거를 대신하지 않는다.

## 내장 원문 조회

- dustagent__history_directory: 현재 실행/세션의 누적 원문 안내 목록 조회. 선택적인 query로 설명·검색어·발췌를 검색하고 cursor로 이어서 조회한다. cursor는0부터 시작하는 목록 위치이며 원문 레코드 번호와 다르다. 페이지 limit은 최대10이며 응답은16KiB 이내로 제한한다. query가 있을 때 각 결과의 matched_by 배열은 description(미검증 요약 설명), keyword(원문 검색어), preview(원문 발췌) 중 일치한 항목을 알려준다. 설명 일치만으로 해당 단어가 원문에 있다고 판단하지 않는다.
- dustagent__history_search: 현재 실행/세션의 원문에 대한 대소문자 구분 문자열 검색. 쿼리는 최대256문자, 결과는 최대20개, 다음 cursor로 이어서 조회한다.
- dustagent__history_read: 1부터 시작하는 원문 index와 offset으로 조회한다. 페이지는 최대16KiB이며 다음 offset을 반환한다. offset은 원문 메시지를 JSON으로 직렬화한 문자열의 UTF-8 바이트 위치다.

도구는 파일 경로나 다른 세션 ID를 받지 않는다. 검색은 페이지별 최대1000개 레코드 또는4MiB를 검사하며, 결과가 없어도 남은 기록이 있으면 cursor를 반환한다. 조회는 잘린 보고서 문자열이 아니라 원문 아카이브를 읽는다. 원문 조회 결과는 누적 보고서 예산 소진으로 모델에게 빈 결과만 전달되는 상황을 피하도록 별도로 제한한다.

## 세션과 체크포인트

ACP 후속 prompt는 같은 세션의 원문 기록을 이어 쓴다. 다른 세션은 별도 기록을 사용한다. 체크포인트에는 압축된 활성 대화와 원문 참조를 함께 저장한다. 재개 시 앱·작업 디렉터리 바인딩과 레코드 수·해시를 검증하며, 원문이 바뀌거나 없으면 재개를 차단한다. 바인딩은 SHA-256으로 기록해 매니페스트 환경변수 값이 참조 메타데이터에 노출되지 않는다. 저장소 환경도 동일하게 유지해야 한다.

기존 체크포인트는 새 참조가 없어도 읽을 수 있지만, 과거에 잘린 도구 결과의 전문을 되살리지는 못한다. 원문 기록과 compact는 불확실한 도구 결과의 강제 재실행을 허용하지 않는다.

## 검증

모델 예산 개선을 포함해 전체217개 테스트, Clippy, 포맷 검사가 통과했다. 자동 예산 계산·배포별 한도·완결된 도구 묶음 보존·기존 설정 호환성, 큰 모델의 조기 압축 방지, 앱 지정 한도의 우선순위, 압축 불가능한 큰 요청과 예산을 초과한 요약 결과의 모델 전달 차단을 검사했다. 누적 색인의 재개·실제 검색어 위치·UTF-8 힌트·목록 페이지·도구 인자의 URL·초대형 도구 이름 처리와, 실제 Dust 프로세스의 목록 조회→검색→원문 읽기 흐름도 검사했다. 실제 Dust 프로세스와 로컬 모델/MCP fixture로100KB 도구 결과의 전문 저장,64KB 이후 원문 검색·조회, 요약 실패 시 보존, 기본 정책의 큰 결과 처리, ACP 세션 격리를 확인했다. 구형 체크포인트의 새 필드 누락도 재개 테스트로 확인했다.

초기 고정 임계값 정책에서는 실제 Codex 모델로 긴 입력3개를 같은 ACP 세션에 보내 모두 end_turn으로 완료했다. 이 과정에서 compact 응답1개가 아카이브에 남았고, 세 입력의 전문이 그대로 보존됨을 확인했다. 모든 모델의 정확한 토큰 계산이나 장기 작업 품질을 입증하는 테스트는 아니다.

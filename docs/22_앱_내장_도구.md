# 앱에 함께 배포하는 도구

앱은 자기 스킬과 실행 도구를 같은 패키지에 담을 수 있다. 스킬은 사용법과 레퍼런스를 제공하고, 도구는 모델이 이름과 JSON 인자를 지정해 호출하는 기능이다. 별도 MCP 서버를 작성하거나 시작할 필요가 없다.

```text
text-stats/
├── app.json
├── tools/
│   └── text_stats.py
└── skills/
    └── text-stats/
        └── SKILL.md
```

`app.json`에 실행 가능한 도구만 명시적으로 선언한다.

```json
{
  "name": "text-stats",
  "package": {"name": "text-stats", "version": "0.1.0"},
  "skills": ["text-stats"],
  "mcp_servers": {},
  "tools": {
    "text_stats": {
      "description": "Count characters, words, and lines in supplied text.",
      "input_schema": {
        "type": "object",
        "properties": {"text": {"type": "string"}},
        "required": ["text"],
        "additionalProperties": false
      },
      "command": "python3",
      "entrypoint": "tools/text_stats.py",
      "args": []
    }
  }
}
```

모델에게 보이는 이름은 `app__text_stats`다. `app`과 `dustagent`는 예약 네임스페이스이며 MCP 서버 이름으로 사용할 수 없다. 다른 앱의 도구와 선언하지 않은 실행 파일은 도구 호출 경로에서 접근할 수 없다. 스킬의 `allowed-tools`나 본문에 도구를 언급하는 것만으로 실행 권한이 생기지 않는다.

## 호출 계약

모델의 인자를 선언한 `input_schema`로 검사한 다음 `command`, 고정 `args`, 패키지 루트 기준 `entrypoint` 순서로 실행한다. 셸 문자열이나 모델 인자를 명령행에 치환하지 않는다. 작업 디렉터리는 앱 루트이며, 표준입력으로 하나의 JSON 값을 전달하고 입력을 닫는다. 표준출력에는 하나의 JSON 값만 출력한다. 디버그 로그는 표준오류로 보낸다.

```python
import json
import sys

request = json.load(sys.stdin)
text = request["text"]
json.dump({"characters": len(text)}, sys.stdout)
```

`input_schema`는 루트가 `object`인 Dust의 기본 JSON 스키마 부분집합을 사용한다. `type`, `properties`, `required`, `additionalProperties`, `items`, `enum`, 숫자·문자열·배열 범위와 `pattern`을 지원하며 지원하지 않는 키워드는 거부한다. 인자 오류, 잘못된 JSON 출력, 비정상 종료는 도구 오류로 모델에 전달되어 기존 턴 예산 안에서 수정할 수 있다.

호출마다 실행 프로세스를 만들고 종료한다. 별도 상주 MCP 프로세스나 MCP 프로토콜은 사용하지 않지만 인터프리터 프로세스는 필요하다. `python3`, `node`, `sh` 등 선언한 실행 환경과 의존성은 호스트에 준비해야 하며 Dust가 설치하지 않는다. 실행 파일은 `tools/` 아래 일반 파일이어야 하고 절대 경로, 상위 경로, 심볼릭 링크를 거부한다.

이 기능은 호출 가능한 도구의 범위를 제한한다. 도구 코드가 실행되면 Dust 프로세스의 사용자 권한과 환경을 사용하므로 파일·네트워크 접근을 제한하는 OS 샌드박스는 별도로 준비해야 한다. 기존 MCP 전용 `chroot` 설정은 앱 도구에 적용되지 않는다.

## 패키징과 복구

스킬 로딩은 스크립트를 실행하지 않는다. `pack`과 `install`은 선언과 파일을 검증하며 실행 훅을 호출하지 않는다. 소스 디렉터리, `.dustpkg` 직접 실행, 설치 이름 실행과 암호화 패키지에 같은 선언이 적용된다.

```sh
dust run ./apps/text-stats "Count this text exactly: hello world"
dust pack ./apps/text-stats --output /tmp/text-stats-0.1.0.dustpkg
dust run /tmp/text-stats-0.1.0.dustpkg "Count this text exactly: hello world"
dust install /tmp/text-stats-0.1.0.dustpkg
dust run text-stats "Count this text exactly: hello world"
```

도구 호출은 기존 보고서·원문 기록·체크포인트에 기록된다. `tool_timeout_ms`와 전체 실행 시간 제한을 사용한다. 앱 도구는 부작용이 있는 것으로 취급하므로 자동 병렬 실행이나 자동 재실행하지 않는다. 시간 초과나 취소 시 외부 부작용이 남았을 수 있으며 확인되지 않은 호출은 재개 전에 결과를 확인해야 한다. 하위 프로세스가 다시 만든 자손 프로세스까지 격리하는 기능은 제공하지 않는다.

도구 선언과 `tools/` 리소스의 내용도 체크포인트 리소스 식별에 포함된다. 내용이 바뀌면 이전 체크포인트 재개를 거부한다. 실행 중 `tools/` 코드를 변경하는 동작은 지원하지 않는다. 결과 파일은 코드·리소스 디렉터리 밖에 저장한다.

참조 구현은 [text-stats 앱](../apps/text-stats/app.json)이다. 스킬 프리로드는 도구의 등록과 별개이며, 스킬 조회가 비활성화된 모델 설정에서도 선언된 앱 도구는 호출할 수 있다.

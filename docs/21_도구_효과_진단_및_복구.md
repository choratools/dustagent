# 도구 효과, 제공자 진단, 불확실한 실행 복구

## 제공자 진단

OpenAI 호환 HTTP 응답과 Codex 스트림에서 제공하는 제한된 진단 정보를 실행 보고서에 보존한다. 가능한 필드는 HTTP 상태 코드, 요청 ID, 추적 ID, `Retry-After` 대기 시간, SSE 종료 상태다. 이 정보는 모델 턴, 재시도, 컨텍스트 압축 응답에 연결된다.

응답 본문, 프롬프트, 인증 헤더, 전체 URL, 스트림 이벤트 내용은 진단 정보에 복사하지 않는다. 제공자가 관련 헤더를 보내지 않으면 필드는 비어 있을 수 있다. 특히 스트림 종료 상태는 전송 계층이 관찰한 상태일 뿐, 모델이 작업을 완료했다는 근거가 아니다.

## 도구 효과 선언

MCP 도구는 기본적으로 `external_unknown`이다. 도구 이름이나 반환값을 보고 안전성을 추정하지 않는다. 앱 매니페스트의 서버별 `read_only_tools`와 `idempotent_tools` 선언만 병렬 처리 판단에 사용한다.

```json
{
  "mcp_servers": {
    "catalog": {
      "command": "catalog-mcp",
      "read_only_tools": ["lookup"]
    },
    "orders": {
      "command": "orders-mcp",
      "idempotent_tools": ["create_or_get"],
      "idempotency_key_argument": "operation_key"
    }
  }
}
```

`read_only_tools`는 서버에서 실제로 읽기만 수행한다고 앱 작성자가 확인한 도구에 한정한다. `idempotent_tools`는 같은 멱등성 키로 중복 요청을 제거하는 서버 계약이 있을 때만 선언한다. `idempotency_key_argument`는 서버 도구 스키마에서 선택적 문자열 속성으로 제공해야 한다. Dust는 실행 전 UUID operation ID를 생성하고 그 값을 도구 인자와 보고서의 `operation_id`에 기록한다. 이 값은 서버의 멱등성 구현을 대신하지 않는다.

## 병렬 실행 경계

다음 조건을 모두 만족하는 한 모델 응답의 도구 묶음만 동시에 실행한다.

- 호출이 2~4개다. 상한은 현재 코어의 고정 한도다.
- 모든 호출이 명시적으로 read-only 또는 idempotent다.
- 각 호출이 서로 다른 MCP 서버에 간다.
- 모든 해당 MCP 클라이언트가 준비돼 있다.

그 외 묶음은 기존 순차 경로로 실행한다. 같은 stdio 서버에 여러 요청을 동시에 보내지 않는다. 병렬 응답은 완료 시간과 무관하게 모델이 요청한 순서로 대화에 넣는다. 효과 선언은 신뢰 경계이며, 잘못 선언한 도구의 부작용을 런타임이 막아 주지는 않는다.

## 결과가 불확실한 외부 호출

실행 전에 체크포인트에 `in_flight`를 기록한다. 이후 프로세스 종료, 시간초과, 전송 오류로 응답을 확인하지 못하면 Dust는 호출을 다시 실행하지 않고 재개를 차단한다. 원격 작업은 이미 반영됐을 수도 있고, 실행되지 않았을 수도 있다. operation ID를 기록해도 Dust가 exactly-once 실행을 보장하지는 않는다.

운영자가 외부 시스템을 확인한 후 결과를 UTF-8 파일에 저장하고, 다음 불확실 호출을 순서대로 조정한다.

```sh
printf '%s' '{"status":"accepted","external_id":"123"}' > observed-result.json
dust reconcile /tmp/dust-run-XXXXXX/state.json \
  --call-id call_abc123 \
  --result-file observed-result.json

dust run crawler --resume /tmp/dust-run-XXXXXX/state.json --max-turns 5
```

예시 경로와 호출 ID는 실제 종료 보고서와 체크포인트 값으로 바꾼다. 결과 파일은 최대 1 MiB의 UTF-8 정규 파일이어야 하며, 심볼릭 링크는 허용하지 않는다. 명령은 MCP를 호출하지 않는다. 제공한 결과는 모델 대화의 도구 응답으로 기록되고 도구 기록의 상태는 `reconciled`가 된다. 외부 시스템을 확인하지 않은 채 임의의 결과를 넣으면 안 된다. 여러 병렬 호출의 결과가 불확실하면 각 호출을 체크포인트 순서대로 조정해야 한다.

실행 보고서에는 조정된 결과를 호출당 최대 64 KiB까지 보존하고 잘림 여부를 기록한다. 전체 결과는 대화와 원문 아카이브에 보존한다. 아카이브는 덮어쓰지 않는다. 조정 시 검증된 원문 기록을 복사한 새 아카이브를 만들고 운영자 조정 표식과 제공 결과를 덧붙인다. 이전 체크포인트와 아카이브는 새 체크포인트 저장 성공 전까지 유효하다.

`dust reconcile`은 사람이 수행한 외부 확인을 증명하지 않는다. 체크포인트에는 누가 어떤 결과를 입력했는지만 남으며, 실제 원격 상태 검증은 운영자의 책임이다. `NotExecuted` 상태의 후속 도구는 이전 불확실 호출이 해결되어도 실행되지 않은 채 유지된다. 모델이 다시 시도할지 여부는 재개 후의 새 판단이다.

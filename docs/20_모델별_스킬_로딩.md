# 모델별 스킬 전달

앱의 `skills`는 사용할 수 있는 스킬을 정한다. `model_configurations`는 허용된 스킬을 모델 입력에 어떻게 전달할지 정한다. 전역 스킬을 추가하거나 MCP 권한을 변경하는 설정이 아니다. 설정은 패키지의 `app.json`에 포함된다.

```json
{
  "skills": ["source-review", "reporting"],
  "model_configurations": {
    "*": {"skills": {"mode": "catalog"}},
    "my-local-model": {"skills": {"mode": "preload"}},
    "gpt-6.1-sol": {
      "skills": {
        "mode": "selective",
        "include": [
          {"skill": "source-review", "paths": ["SKILL.md"]},
          {"skill": "reporting", "paths": ["references/output-format.md"]}
        ],
        "max_preload_bytes": 32768
      }
    }
  }
}
```

## 선택 규칙

실제로 선택한 모델의 ID와 정확히 일치하는 설정, `*`, 기본 `catalog` 순서로 선택한다. `*` 외에 접두사·정규식 매칭은 없다. CLI `--model`은 앱의 `default_model`보다 우선하며, provider가 선택한 실제 기본 모델도 이 규칙을 따른다. ACP에서도 모델을 선택해 core를 만들 때 같은 설정이 적용된다.

라이브러리 provider는 `LlmProvider::model_id()`로 실제 ID를 제공할 수 있다. 값이 없으면 앱 `default_model`을 사용하고, 그마저 없으면 `*` 또는 catalog를 사용한다. `Box`와 `Arc`는 ID 조회를 내부 provider에 전달한다.

## 전달 모드

| 모드 | 초기 내용 | 추가 자료 |
|---|---|---|
| `catalog` | 이름·설명·스킬 조회 방법 | 모델이 필요할 때 조회 |
| `preload` | 카탈로그 + 모든 허용 스킬의 `SKILL.md` | 상대 파일 목록을 보고 조회 |
| `selective` | 카탈로그 + `include`에 지정한 파일 | 나머지는 상대 파일 목록을 보고 조회 |

`preload`는 references를 자동으로 읽지 않는다. `selective`는 지정한 파일만 읽으며, `SKILL.md`도 원하면 명시해야 한다. `include`는 selective에서만 허용하고, 비어 있는 선택·중복 스킬·중복 파일을 거부한다.

preload 모드의 JSON 입력은 `catalog`, `resources`, `preloaded`와 조회 지침으로 구성된다. `resources`의 각 항목에는 `skill`, `path`, `preloaded`가 있고, `preloaded` 내용에는 `skill`, `path`, `content`가 있다. 예를 들어 `source-review`의 `SKILL.md`에서 `references/checklist.md`를 언급하면 다음 도구 호출로 읽는다.

```json
{"skill":"source-review","path":"references/checklist.md"}
```

도구 이름은 `dustagent__read_skill`이다. 파일 경로는 해당 스킬 디렉터리를 기준으로 하며 호스트 절대 경로를 모델에게 알려주지 않는다. 파일 목록은 실제 존재하는 허용 경로를 나타낸다. 바이너리 파일을 텍스트 조회 도구로 읽을 수 있다는 뜻은 아니다. 스크립트를 preload하거나 읽어도 실행하지 않는다.

## 크기와 오류

`max_preload_bytes` 기본값은 32,768바이트이고 허용 범위는 1~262,144다. preload와 selective에서는 본문뿐 아니라 카탈로그·파일 목록·출처·조회 지침을 포함한 직렬화된 스킬 입력 전체를 검사한다. UTF-8 바이트와 JSON 이스케이프를 포함한다. catalog에서는 기존 메타데이터·패키지 제한을 유지하며 이 preload 예산을 적용하지 않는다.

예산 초과, 없는 파일, 비 UTF-8 내용, 미허용 스킬, 경로 탈출 및 심볼릭 링크는 모델 호출 전에 오류를 반환한다. 조용히 자르거나 catalog 모드로 바꾸지 않는다. 개별 텍스트 파일은 기존 64 KiB 제한도 적용된다. 기본적으로 활성화된 컨텍스트 관리에서도 모델 입력 전체의 추정 한도를 별도로 검사하므로 preload 예산을 크게 잡아도 모델 입력에 반드시 들어가는 것은 아니다. `compaction.enabled`를 끄면 이 추정 토큰 예산 검사는 적용하지 않으며, 대화의 메시지 수·전체 바이트 한도는 유지한다.

## 로딩과 재개

`with_app_resources`에서 선택한 입력을 만들어 보관한다. 매 턴 디스크에서 다시 읽거나 추가 모델 호출을 하지 않는다. 스킬 입력은 시스템 메시지로 전달되고, 기존 컨텍스트 관리가 지침으로 보존한다.

모델별 설정이 있는 경우 선택된 정책과 실제 전달 내용도 자원 바인딩에 포함한다. 정책 또는 전달 내용이 다른 체크포인트·세션은 그대로 재개하지 않는다. 설정이 없는 기존 앱의 자원 바인딩은 유지한다. 로컬 패키지 파일은 실행 동안 바꾸지 않아야 한다.

MCP 도구 정의의 전달 방식은 이 설정으로 바뀌지 않는다. 전체 앱 도구 정의는 여전히 시작할 때 수집해서 모델 요청에 전달한다.

## 검증 범위

모의 provider로 전달 내용, 실제 모델 ID 우선순위, 참조 파일 출처, 설정 오류와 경로·예산 경계를 검사한다. 실제 `dust` CLI와 로컬 HTTP 서버로 `--model`의 요청 본문, 같은 정책의 체크포인트 재개, 정책 변경 시 HTTP 요청 전 거부를 확인한다. 초기 preload가 모델 입력 예산을 넘을 때 호출 전 중단하는 경로도 검사한다. 이 검증은 전달·재개 동작을 확인하며 실제 모델의 스킬 활용 품질 향상을 입증하지 않는다.
